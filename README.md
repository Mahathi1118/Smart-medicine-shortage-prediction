# AI-Based Smart Medicine Shortage Prediction and Inter-Hospital Resource Sharing System (MediBridge)

A web-based **decision-support** prototype that predicts medicine shortages, raises alerts, and recommends
hospitals that can share surplus or near-expiry stock. Final decisions stay with authorised hospital staff.

> **Data note:** No real hospital or patient data is used. All data in `data/` is **synthetic**, generated by `generate_data.py`.

## Problem
Medicine shortages occur due to changing demand, emergencies, supply delays and weak inventory management,
while other hospitals hold excess stock that expires unused.

## Features
- Forecasts the next 14 days of demand for every hospital and medicine (trend + weekly pattern, scikit-learn).
- Shortage risk (HIGH / MEDIUM / LOW) by comparing days of stock with supply lead time.
- Recommends donor hospitals using urgency, quantity, expiry status and geographical distance.
- Protects donors: a hospital only shares stock above its own forecast demand plus a 20% safety buffer.
- Flags near-expiry stock that is unlikely to be used in time and suggests it for redistribution first.
- Mobile-friendly dashboard and a JSON API.

## Tech stack
Python, Flask, pandas, NumPy, scikit-learn, HTML/CSS/JavaScript.

## Project structure
```
app.py                  Flask web app
generate_data.py        Creates synthetic data
medishare/predictor.py  Demand forecasting and risk levels
medishare/recommender.py  Hospital recommendation and near-expiry alerts
medishare/service.py    Builds the dashboard data
templates/index.html    Dashboard page
data/                   Synthetic sample data (CSV)
tests/test_core.py      Test cases
docs/technical_design.md  Architecture diagrams and design
```

## Setup and run
Requires Python 3.10 or newer.

```bash
git clone <this-repository-url>
cd smart-medicine-shortage-prediction
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt
python generate_data.py           # optional: regenerates the synthetic data
python app.py
```
Open http://127.0.0.1:5000 in your browser.

## Environment variables
Optional. Copy `.env.example` and set values if needed. No secrets or API keys are required.

| Variable | Default | Meaning |
|----------|---------|---------|
| `PORT` | 5000 | Port the web app runs on |
| `DATA_DIR` | data | Folder containing the CSV files |

## API
`GET /api/dashboard` returns predictions, recommendations and near-expiry alerts as JSON.

## Run the tests
```bash
python -m unittest discover tests
```

## Sample data
`data/sample_data.csv` (daily consumption), `data/inventory.csv` (stock, expiry, lead time) and
`data/hospitals.csv` (fictional hospitals with coordinates).

## Limitations and future work
Prototype using synthetic data and a simple forecasting model. Future work: real hospital data integration,
stronger models (e.g. gradient boosting, LSTM), road-distance routing, user login, and regulatory checks for transfers.

## Live demo (GitHub Pages)
The root `index.html` is a static snapshot of the dashboard (synthetic data embedded), so it works on GitHub Pages
with no server. After changing data or code, regenerate it with `python export_static.py`.
Note: `templates/index.html` needs the Flask server (`python app.py`); opening it directly shows only "Loading...".
